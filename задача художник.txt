# Art Bible MVP для Tile Puzzle Home

## Краткое резюме

Ниже — сжатый, но полный **production-ready Art Bible** для первой релизной версии **Tile Puzzle Home** под **Unity 6000.3.20f1, 2D URP, WebGL, Yandex Games**. Спецификация сознательно ограничивает количество и размер ассетов: это снижает draw calls через Sprite Atlas, упрощает импорт в Unity, помогает держать загрузку и память под контролем в WebGL, а также лучше укладывается в требования Яндекс Игр по адаптивности, сохранению прогресса, UX и лимиту размера архива. Unity рекомендует объединять одновременно используемые спрайты в Sprite Atlas и разделять атласы по сценам/частоте использования/настройкам компрессии; WebGL-память и распаковка `.data` чувствительны к лишним текстурам, а Яндекс отслеживает **Game Ready** и **TTI** в DevTools, поэтому для MVP здесь задан жесткий, практичный арт-бюджет. citeturn7view0turn7view3turn7view5turn7view6turn11view0

Эта версия исходит из **портретного baseline 1080×1920**, одного игрового режима, поля **7×7**, **5 пазлов** и **5 открываемых фонов**. Все размеры ниже заданы так, чтобы художник мог рисовать без двусмысленности, а Codex — сразу импортировать и собирать UI, Atlas’ы, sorting, анимации и VFX без дополнительных вопросов. Спецификация также учитывает, что Unity импортирует распространенные форматы изображений, включая PNG/PSD/TGA/TIFF/SVG; при этом **WebP не указан в списке стандартных image importers для текстур**, поэтому для runtime-ассетов здесь принят стандарт **PNG с альфой**, а WebP допускается только для внешних превью/референс-листов вне Unity. citeturn9view2turn9view3

## Производственные ограничения и глобальные стандарты

### Базовая постановка экрана

**Проектный стандарт MVP**

| Параметр | Значение |
|---|---:|
| Ориентация | Portrait |
| Baseline resolution | **1080 × 1920 px** |
| Safe UI zone | **X: 60–1020, Y: 80–1840** |
| Gameplay field zone | **60, 290 → 1020, 1250** |
| Canvas reference | 1080 × 1920 |
| Мін. интерактивный размер | **88 × 88 px** |
| Основная логика скейла | scale by height, с аккуратным letterbox/pillarbox |

Эти значения выбраны не «для красоты», а под требования Яндекс Игр: элементы управления должны быть достаточно крупными, чтобы исключать случайные нажатия; игра должна корректно масштабироваться при изменении окна; активное поле не должно выходить за экран; интерфейс не должен требовать дополнительных прокруток и должен быть удобен для игры одной рукой. citeturn11view0

**Правило:** не использовать более 2 dominant accents на одном экране. База — теплые нейтрали, один теплый CTA-акцент, один прохладный контраст для дождя/вечера/нейтрализации.

### Общие художественные правила

| Параметр | Стандарт |
|---|---|
| Runtime delivery | **PNG RGBA** |
| Master source | PSD / AI / SVG allowed |
| Pixels Per Unit | **100** |
| Outline | 4 px на базе 256 px; 2 px на 128 px; 6 px на 512 px |
| Shadow | мягкая теплая, `#6F4E43`, 12–18% opacity |
| Bloom | только для света/награды/огня, 12–18%; не на тексте |
| Global opacity | 100%, если не указано иное |
| Filter look | мягкий, не пиксель-арт |
| Texture sizing | по возможности степени двойки |

Unity рекомендует задавать импорт текстур через Texture Import Settings и использовать platform overrides; для текстур предпочтительны размеры, близкие к степеням двойки. Sprite Atlas в Unity уменьшает количество draw calls, а best practice — разделять атласы по сценам, частоте использования и профилям компрессии. Для WebGL это особенно полезно, потому что build-данные распаковываются в память браузера, а Unity heap стоит держать как можно меньше. citeturn7view0turn7view1turn7view2turn7view3turn9view3turn10search3

### Фоны, пазлы и сценовые анимации

Для MVP выгоднее не рисовать «тяжелые» цельные фоновые полотна на 4K, а собирать каждую сцену из **трех слоев** плюс одной легкой animated detail. Это лучше для WebGL-памяти, проще для атласов и дает Codex возможность включить параллакс/тайминги без новых ассетов. Unity прямо рекомендует дробить atlas’ы по наборам спрайтов, используемых одновременно, а WebGL страдает от избыточного asset data в памяти браузера. citeturn7view0turn7view3

## Настройки экспорта и импорта для Unity

### Решение по форматам файла

Поскольку Unity штатно импортирует PNG, PSD, TGA, TIFF, SVG и другие стандартные форматы изображений, а в официальных списках supported image formats **WebP не присутствует как обычный texture import format**, для MVP стоит зафиксировать простой pipeline: **master source** можно хранить как PSD/AI/SVG, но **в Unity класть PNG**. Это делает импорт и atlas packing предсказуемыми и не создает сюрпризов на CI/у Codex. citeturn9view2turn9view3

### Таблица import/export settings

| Asset group | Runtime source | Max Size | Texture Type | Sprite Mode | Mesh Type | PPU | Filter | Mipmaps | Compression | Crunch | Atlas | Notes |
|---|---|---:|---|---|---|---:|---|---|---|---|---|---|
| Tile icons | PNG RGBA | **256** | Sprite (2D and UI) | Single | Tight | 100 | Bilinear | Off | Normal Quality / Automatic | Off | `atlas_tiles_gameplay` | alpha crucial |
| Tile plates / board / tray | PNG RGBA | **1024** | Sprite | Single | Full Rect | 100 | Bilinear | Off | Normal Quality / Automatic | Off | `atlas_gameplay_core` | 9-slice not needed except frame |
| UI buttons/panels | PNG RGBA | **1024** | Sprite | Single | Full Rect | 100 | Bilinear | Off | Normal Quality / Automatic | Off | `atlas_ui_core` | panels/buttons via 9-slice |
| UI icons | PNG RGBA | **256** | Sprite | Single | Tight | 100 | Bilinear | Off | **None** if edge damage visible; else Normal | Off | `atlas_ui_icons` | keep crisp |
| Puzzle full images | PNG RGBA | **2048** | Sprite | Single | Full Rect | 100 | Bilinear | Off | High/Normal Quality Automatic | Off | `atlas_puzzles` | show only in puzzle screen |
| Background layers | PNG RGBA | **1024** or **2048** | Sprite | Single | Full Rect | 100 | Bilinear | Off by default | Normal Quality / Automatic | Off | scene atlas | enable mipmap only if shimmer confirmed |
| VFX sprites | PNG RGBA | **256** | Sprite | Single / Multiple for sheets | Tight | 100 | Bilinear | Off | Normal Quality / Automatic | Off | `atlas_vfx` | additive-ready |
| Sprite sheets | PNG RGBA | exact sheet | Sprite | **Multiple** | Tight | 100 | Bilinear | Off | Normal Quality | Off | scene/vfx atlas | slice in Sprite Editor |

Unity указывает, что import параметрами для 2D спрайтов управляет **Sprite (2D and UI)**, а Sprite Atlas может переопределять filter mode и platform-specific settings для упакованных спрайтов. Также Unity прямо дает platform-specific texture overrides для выбора Max Size, формата и компрессии; для desktop рекомендуемые GPU formats включают DXT1 для RGB и BC7/DXT5 для RGBA, но для Web поддержка зависит от браузера/платформы, поэтому для MVP разумнее оставить **Format = Automatic** и управлять качеством через `Compression` и `Max Size`. citeturn7view1turn7view2turn10search0turn10search1turn10search3turn9view0

### Sprite packing и atlas policy

- Использовать **Sprite Atlas V2**.
- Делать atlas’ы **по сценам и по типам использования**, как указано выше.
- **Atlas max size:** 2048 для крупных групп, 1024 для icons/VFX.
- **Padding:** 4 px.
- **Allow Rotation:** On для icons/VFX, Off для backgrounds/panels.
- **Tight Packing:** On для icons/VFX, Off для panel/button art.
- **Variant atlases:** не нужны для MVP.

### WebGL-ориентированные ограничения

| Правило | Стандарт MVP |
|---|---|
| Unzipped archive | **< 100 MB** |
| Art budget on disk | целиться в **≤ 20–25 MB** PNG total |
| Active resident art in memory | держать **как можно меньше**, не грузить все фоны одновременно |
| Default atlas ceiling | 2048 |
| Giant single textures | избегать |
| Decompression fallback | не рассчитывать на него как на «норму» |
| Local/self-host test | если не Yandex-hosting, использовать корректные `Content-Encoding` и `application/wasm` |

Эти лимиты опираются на три вещи: Яндекс требует, чтобы разархивированный размер игры не превышал **100 MB**; Unity Web хранит build data и распакованные asset data в памяти браузера; а нативная browser decompression и `application/wasm` важны для быстрого старта при self-host/локальном тестировании. На Yandex-hosting часть серверной конфигурации платформа берет на себя, но локальные QA-прогоны все равно полезно делать корректно. citeturn11view0turn7view3turn9view1

### Отдельно про Yandex SDK-экран загрузки и Ready

Визуально это означает: **не рисовать длинный кастомный preloader для MVP**. Яндекс требует корректную инициализацию SDK, вызов `LoadingAPI.ready()` тогда, когда игра реально готова к взаимодействию, и отсутствие лишних экранов загрузки в этот момент. Следовательно, splash/UI-пакет должен быть минимальным: логотип, чистый HUD и быстрый first paint. citeturn5view1turn5view2turn7view4turn11view0

## Чек-лист приемки и немедленный план производства

### Чек-лист приемки для каждого ассета

**Для tile icons**
- Читается в размере **88×88 px**.
- Отличается от остальных тайлов в grayscale preview.
- Не выходит за safe area.
- Outline равномерный, без дрожащих толщин.
- Нет микродеталей, исчезающих при уменьшении.
- PNG с чистой альфой, без белых/темных fringe-краев.
- Размер файла в лимите.

**Для UI**
- Нет вшитого текста в кнопках и панелях.
- Работает как 9-slice там, где это требуется.
- Контраст текста на поверхности достаточен.
- Иконка читается на **32 px**.
- Нет лишнего glow на мелких элементах.
- Нет кислотных цветов вне палитры.

**Для backgrounds**
- Слои совпадают по перспективе.
- В центральной зоне нет перегруза под поле/панели.
- Foreground не конфликтует с tray и HUD.
- В desktop-crop safe area композиция не ломается.
- Нет «грязного» шума и мелкой текстуры.
- Размер слоя в лимите.

**Для puzzle images**
- Главный фокус остается внутри **1280×1280** safe area.
- Края не содержат критичных деталей.
- Изображение выглядит цельно и как пазл, и как reward-preview.
- Нет текста/логотипов/рамок.

**Для VFX**
- Луп бесшовный.
- На 0.5x и 1.5x масштабах выглядит мягко.
- В PNG нет обрезанных световых хвостов.
- Sprite sheet правильно нарезается на кадры.
